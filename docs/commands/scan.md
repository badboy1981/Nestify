# 🔍 Scan Command (`nestify scan`)

The `scan` command is the core structural scanner of **Nestify**. It recursively traverses a project directory, applies `.nestifyignore` rules to strip out build clutter and binary artifacts, and generates structured outputs in both **JSON** and **Markdown Tree** formats.

---

## 🛠️ Usage & Options

```bash
nestify scan [options]
```

### Flags & Options

| Flag | Short | Description | Default |
| --- | --- | --- | --- |
| `--path` | `-p` | Target directory path to scan. | `.` (Current Directory) |
| `--tree` |  | Generates a human-readable ASCII tree report (`.md`). | `false` |
| `--folders-only` |  | Restricts traversal to directories, ignoring all files. | `false` |
| `--depth` | `-d` | Limits directory traversal depth (`0` for unlimited). | `0` |

!!! info "Cross-Platform & Shell Agnostic"
    Nestify is compiled into a single native binary with zero external dependencies. All CLI commands run identically across **Windows (PowerShell / CMD)**, **macOS**, and **Linux (Bash / Zsh)**. Learn more about [Shell Agnostic Execution](https://www.google.com/search?q=../getting-started/quickstart.md%23cross-platform-execution).

---

## 💡 Examples & Common Use Cases

### 1. Basic Directory Scan (JSON Output)

Scans the current working directory and saves a timestamped JSON node report inside (`Nestify-Report/`).

```bash
nestify scan
```

### 2. Generate a Visual Directory Tree

Produces both the default JSON report and a clean ASCII tree Markdown report (`Nestify-Report/PROJECT_TIMESTAMP.md`).

```bash
nestify scan --tree
```

### 3. High-Level Clean Architecture View

Excludes files from the scan to inspect only the folder hierarchy up to a depth level of 2.

```bash
nestify scan --folders-only -d 2
```

### 4. Scan a Specific External Path

Target any folder on your file system without leaving your current terminal working directory.

```bash
nestify scan --path ./projects/MyApi --tree -d 3
```

## 🔒 Ignore Logic Integration

The `scan` command automatically respects:

1. Standard built-in default ignore patterns (`.git/`, `.DS_Store`, etc.).
2. Project-level `.nestifyignore` files located in the target scanning directory.

??? tip "Need to ignore language-specific build folders?"
     Run `nestify ignore-use <tech-stack>` before scanning to automatically suppress heavy folders like `node_modules/`, `bin/`, `obj/`, or `vendor/`.
